| D53 | **Proof of presence is the office's public IP, checked in the database.** Check in / out are RPCs the **browser** calls with the user's own session; the RPC reads the caller's IP from the request headers (`current_setting('request.headers')`) and accepts only an address inside an active `office_network` row. A Server Action cannot be used because Supabase would then see the app server's IP, and a value passed in by the client is never trusted. The row stores only the matched network id, never the raw IP (DPDP). Check-out from outside the office is allowed but **flagged**. A person on mobile data, a VPN or iPhone Private Relay can send a **manual request with a reason** that a lead approves. Timestamps are set by the database, never the browser. Rule tests fake the headers with `set_config('request.headers', ...)` in PGlite | Business rules live in the database; an app-side check would be bypassed by calling the RPC directly. Honest-person presence, not tamper-proof (a shared login or a VPN into the office defeats any network check) |
| D54 | **What we found on the office network (probed 18 Nov 2026 from a machine on the Wi-Fi).** The gateway is an ISP-supplied **GPON ONT** doing PPPoE. The public IPv4 belongs to the ISP, a real public address (**not CGNAT**) but from a **PPPoE pool, so probably dynamic**. No IPv6. Cloudflare and Supabase Auth both see the same address (the only two sign-ins on record, 16 to 17 Nov, are from it). Consequences: there is no router to script, so the allowlist cannot be fed by the router; instead the founder gets a **"Trust this network" button** (founder-only RPC that records the caller's current IP as an office network, keeps older ones, shows when each was last confirmed), the app tells the founder when several tagged people fail the network check on the same day ("the office IP may have changed"), and we **ask the ISP for a static IP**. Allowlist entries are `cidr` so IPv6 can be added later | A dynamic address must not silently lock everyone out; fixing it takes one click, not a code change. A static IP from the ISP removes the problem |
